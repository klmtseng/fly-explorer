## 本輪發現與處置

### F1(P1,已修)README 對閘門的覆蓋宣稱是假的
`README.md` 寫「每支都有 `--self-test` 或負向案例,證明它擋得住錯的東西」。機器重數:
`audit_numbers.py` 與 `audit_claims.py` **兩支都沒有**,而且 `audit_numbers.py` 結尾只有 print、
沒有 `sys.exit`,**永遠 exit 0**——它被列在閘門清單裡,卻是一支不可能 FAIL 的「閘門」
(歷史失手挑戰 [3] 恆真 PASS 的同型)。

處置:
- `audit_numbers.py` 升級成真閘門:已知孤兒數字凍結在 `audit/known_orphans.tsv`(每筆附人工查到的實際出處),
  本次算出的集合與該表不符即 exit 1——多一筆(新數字沒出處)或少一筆(登記過期)都擋。
- 兩支都補 `--self-test` 負向案例,實跑通過。
- 自測第一版**自己就是壞的**:負向案例只改中文那份,而同一個數字在英文版還有一份,集合去重後孤兒沒消失,
  於是「拿掉一筆已登記孤兒」的案例 exit 0 被誤判成「閘門擋不住」。改成中英兩份一起改才真的觸發。
  (教訓:自訂閘門的第一版量尺預設是錯的,要先看它報出來的清單長什麼樣。)

### F2(P2,已查證)7 筆「查無出處」的數字,全部有出處
`audit_numbers.py` 報 7 筆孤兒。逐條追:

| 數字 | 實際出處 | 為何比對不到 |
|---|---|---|
| 1,771(×2) | `optic-lobe` 卡事實欄 892+879 | 檢查器只在同一張卡的事實欄比對,跨卡引用抓不到 |
| 八百六十億 | 同卡事實欄 861 ± 81 億 | 中文數字轉換後 860 億 vs 861 億,差 0.1% |
| 167,000 | 16.7 萬 = 166,691(`docs/data_facts.md`) | 四捨五入到三位有效數字 |
| 54.8 | 548,000(Winding et al. 2023) | 單位換算(萬)後字面不同 |
| 114.9(×2) | `docs/verification_log.md` 翅膀下壓肌 114.88 ± 1.37 | 四捨五入到一位小數 |

**我原本的假設是錯的**:第一眼以為 114.9 在任何文件裡都查不到,寫下來之前先 grep 才發現是 114.88 的四捨五入。
(重現閘門的價值:沒重現的發現只是假設。)

### F3(P2,已修)人腦神經元數的措辭
`why-fly` 小朋友層原文「人腦有八百六十億個神經細胞」,而事實欄是 861 ± 81 億(Azevedo 2009 有誤差範圍)。
改成「大約八百六十億」,英文同步 `about 86 billion`。

### F4(P2,已修)沒有出處的數字下界
`why-fly-history` 原文「腦約 10 萬到 16.7 萬顆神經元」。16.7 萬有出處(166,691),**10 萬沒有**;
而且 166,691 是整個中樞神經系統(腦+腹神經索)不是「腦」。改成「整個中樞神經系統約 16.7 萬顆神經元」,英文同步。

### F5(P2,已修)內文引用的論文數字不受 `citation_record_lint` 覆蓋
`citation_record_lint.py` 只驗事實欄的 ◆;寫在正文裡的「(Winding et al. 2023)3,016 顆神經元、54.8 萬突觸」
不在覆蓋範圍內,等於一條沒被任何閘門看過的引用。
處置:實查該論文(PMC7614541 摘要親讀,原句 "comprising 3016 neurons and 548,000 synapses"),
補成 `whats-next` 卡的正式事實欄(◆,附 DOI 與親讀範圍)。
**殘留缺口(不在本輪保證內)**:其他正文引用若帶數字,仍可能逃過 lint。已知的三處
(Fotowat 2009、Reiter 2001、Van Essen 2003)本輪人工掃過,都有對應事實欄 source。

### S5 頻寬(本輪唯一的 P1 系統風險)

體檢 agent 用未壓縮大小算出「單次 2.25 MB → 約 4.5 萬次觸頂」。**主線自己重量**:
瀏覽器會送 `Accept-Encoding`,Vercel 全部回 brotli,實際傳輸如下。

| 檔案 | 未壓縮 | 實際傳輸(br) |
|---|---|---|
| index.html | 34,100 | 11,120 |
| assets/index-*.js | 704,604 | 202,911 |
| data/soma.bin | 1,120,220 | 944,942 |
| data/hexmap.json | 211,657 | 69,877 |
| data/escape_edges.json | 44,437 | 9,791 |
| data/scenarios/escape_trace.json | 39,645 | 4,432 |
| data/scenarios/escape_spikes.json | 1,581 | 656 |
| data/scenarios/escape.bin | 89,749 | 78,536 |
| **合計** | **2,245,993** | **1,322,265(1.26 MiB)** |

Vercel Hobby 方案 Fast Data Transfer 上限 100 GB/月 → **約 7.5 萬到 8.1 萬次完整首訪**。
超過的後果是頻寬功能停到下個計費週期,等於宣傳期網站掛掉。

處置:新增 `vercel.json`,`/assets/*` 給 `max-age=31536000, immutable`(檔名帶內容雜湊,改內容一定換檔名),
`/data/*` 給 `max-age=86400` + 一週 `stale-while-revalidate`。原本全站是 `max-age=0, must-revalidate`,
每次重新整理都要往返。**這只省重複造訪,救不了首訪**;真要降首訪成本得動 `soma.bin`(壓縮後 945 KB,佔七成),
那是改資料格式,不在本輪範圍。

### 冷審 P1-1(確認,已撤回)「70 倍相變」被本站自己出貨的資料推翻
