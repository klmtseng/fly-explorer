# 視覺出處規範 — 畫面上什麼是真的、什麼是我們加的

寫於 2026-09-12,使用者要求。**這份規範必須在寫任何動畫程式碼之前定案並遵守。**

## 為什麼需要它

我們的資料只有**神經系統**。連接組裡沒有肌肉、沒有翅膀、沒有腳、沒有身體。
所以畫面上任何身體動作都是**我們畫的**,不是資料。

而且模型本身還有一個斷點:**視覺前端傳不過去**
(刺激視覺柱只驅動 LC4 到 1.23Hz、LPLC2 全靜默、訊號到不了任何肌肉;
 下游 LC4/LPLC2 → 巨纖維 283Hz → 肌肉則完美運作,見 verification_log)。
所以「眼睛看到 → 偵測器啟動」那一步是我們**注入**的,不是算出來的。

三種東西混在同一個畫面上,觀眾必須分得出來,否則就是在教錯的東西。

## 四個層級與它們的視覺語言

| 層級 | 是什麼 | 視覺語言 | 顏色 |
|---|---|---|---|
| **① 真實解剖** | 神經元的三維位置、連線 | **發光的點**,加色混合 | 各族群色(現有) |
| **② 真實模擬** | 放電活動 | **同一批點的亮度**,亮度=真實放電率 | 同上,加白 |
| **③ 我們注入的** | 模型算不出、由我們直接給的輸入 | **虛線 + 流動動畫**,永遠帶文字標籤 | `#C8629E` 洋紅 |
| **④ 我們畫的** | 外殼、肌肉、翅膀、腳、身體動作 | **線稿為主,絕不發光**;實體小視窗可加**平塗淡色**(普通混合、不進 bloom、無漸層光暈) | `#9AA8C4` 冷粉筆;淡色=黃褐身/磚紅眼/黑環(◆ 文獻描述) |
| **④' 肌肉與神經→肌肉連線** | 胸腔肌纖維、運動神經元細胞體到肌肉的線 | **琥珀色線稿**,畫在 bloom 之後的獨立 scene,普通混合、不發光;濃淡=顏色往黑收(等同不透明度),跟著真實運動神經元亮度 | `#E8A34A` 琥珀——跟外殼分開色,因為它代表「連接組裡**沒有**的那一段」 |

## 核心規則:資料會發光,圖解不會

```
發光(emissive + additive blending)  →  這是資料
不發光(線稿 wireframe)             →  這是我們畫的
```

這個區分**不需要圖例就感覺得出來**。圖例是補強,不是唯一依據。

### 混合情況:形狀是我們畫的,動作由真資料驅動

肌肉收縮、翅膀拍動屬於這類——**形狀是④,驅動它的數字是②**。

處理方式:**維持線稿不發光**,用**線寬與不透明度**表現強度,不用亮度。
這樣「它在動」看得見,但「它不是資料」這件事仍然成立。

> ✗ 錯誤做法:翅膀肌發光,亮度跟著 DLMn 放電率走 —— 觀眾會以為肌肉是資料的一部分
> ✓ 正確做法:翅膀肌是線稿,線變粗、輪廓變實,旁邊標「由 DLMn 114 Hz 驅動」

## 硬性禁止

1. **不得讓畫面暗示訊號從眼睛一路自然傳到肌肉。** 那一段在模型裡是斷的。
   逃跑動畫的第一步必須有可見標記說明它是注入的。
2. **不得把④畫成發光的。** 一旦肌肉會發光,①②④ 三層就糊成一團。
3. **不得只靠圖例交代。** 圖例會被略過;視覺語言本身要能自證。
4. **每個出現在畫面上的數字都要指得出產生它的腳本**(沿用內容卡的出處規則)。

## 常駐圖例(三行,固定在播放器下方)

```
● 發光     真實神經元位置與活動
◆ 洋紅     模型算不出,我們注入的
◇ 線稿     我們畫的身體(冷灰)、肌肉與神經→肌肉連線(琥珀,已實作)
```

數字的出處不放圖例,放在**每段階段標籤下方**(`content/stages.json` 的 `src` 欄位,前端以小字渲染)。

## ③ 注入/我們加的:目前有兩段

- **前奏**(t<0):偵測器被我們點亮——模型視覺前端傳不過去。
- **結局**(t>250 ms,2026-09-14 增):最後一幀 ×(1−k)² 淡出、翅膀收回。模型不會自己停,這段是使用者要的靜止收尾,
  時鐘/字幕洋紅明標「我們加的結局」。

## 已知需要標示③的項目清單

## ★ 我們獨立驗證了 blendi 的定性宣稱,並且量化了它

blendi 說「medulla 運動路徑靜默,逼近訊號是**解析畫上去**的」——**指名的正是 LC4/LPLC2,
跟我們測的是同一組神經元**。我們的實測給了它數字:

> 刺激成片視覺柱 → LC4 僅 **1.23 ± 0.03 Hz**、LPLC2 **0.00**、訊號到不了任何運動神經元。
> 直接刺激 LC4/LPLC2 → 巨纖維 **283.80 ± 0.45 Hz**、跳躍肌 73.00、翅膀下壓肌 114.88。

**兩個獨立實作在同一個地方斷掉,這不是誰寫錯程式,是模型層級的限制。**

## 採用:README 首段的 STATUS 行(抄 doomfly)

本專案的 README 與網站「關於」頁必須在最前面放一行狀態,格式:

```
Status: <做到什麼> / <明確沒做到什麼>。
視覺前端未通過驗證:刺激視覺柱僅驅動 LC4 至 1.23 Hz、LPLC2 為 0,訊號到不了運動神經元。
下游(LC4/LPLC2 → 巨纖維 → 肌肉)通過驗證且可重現。
```

**理由**:把失敗閘門寫在第一段,比寫在「限制」章節強——限制章節會被略過,首段不會。
這也與本專案「內容卡每個事實帶出處標記」的做法一致。

## 避免:把免責聲明埋在口語閒聊裡(ornata/fly 的反例)

"This code is literally 100% vibe coded... I have not reviewed the code" 與
"not a validated living fly" 混在同一段輕鬆語氣裡。
略讀的人抓不到可信度訊號,而略讀是常態。**免責必須與正文同等份量、同等位置。**

## 電壓計(2026-09-13 新增)

右上角的「巨纖維膜電壓」是**資料層**:引擎 `--trace-out` 每 0.1 ms 原樣輸出的膜電壓,
與出貨的放電資料來自**同一次執行**(同 seed、同協定),不做平滑、不做美化。
它存在的理由:畫面上的點只在放電時亮,但放電前電壓已經在爬——那段是看不見的,
電壓計把它畫出來,「突然亮」的來源就是跨過 −45 mV 那一刻。
判閾值前記錄,所以跨線瞬間會略高於 −45(峰值 −44.2),那是正確的,不是誤差。


## 實體小視窗 PiP(2026-09-13 新增)

`src/pip.ts`:同一個 renderer 以 scissor 在 #pip 方框區域再畫一次,獨立場景、側視相機,
裡面是第二隻線稿果蠅(`buildShell(cloud,{opacity:0.55,tint:true})`,線稿加平塗淡色,仍普通混合、不經 bloom、不發光)。
2026-09-13 使用者要求「稍微上點色、比例照真實果蠅」:比例與顏色的出處在 docs/verification_log.md §果蠅身體比例。
**主畫面的外殼維持純線稿不上色**——它疊在神經元上,上色會蓋住資料。

**驅動 = 真實放電,幅度 = 示意**:
- 翅:DLMn+DVMn 24 顆節點亮度平均(線層 nodeBright,全解析度,不受手機抽樣影響)
- 跳躍:TTMn 2 顆取最大值,帶包絡(0.94/幀)——它只放電 1 次,不撐住會一閃就沒
- 拍翅相位用**模擬時間**推進,週期 5 ms(果蠅約 200 Hz,文獻常值,本專案未親驗);暫停即停、拖曳一致
- 我們只知道「哪條肌肉的神經元在放電」,**不知道肌肉收縮多少、身體位移多少**——
  連接組沒有肌肉、沒有物理。方框內註記逐字寫明「幅度是示意——連接組沒有肌肉與物理」。
- 讀數每幀顯示兩組強度百分比,讓人看到動作跟著數字走。
