# 科學宣稱的檢查與評估(2026-09-17 建)

前三輪 validity audit 修的是「數字對不對、撤回有沒有回流、英文有沒有殘留中文」。
剩下沒有任何機器擋得住的那一類是:**科學上說錯,但用詞乾淨**——句子謹慎、有限定語、
數字也對得上自家資料,推論卻是錯的。這份文件講怎麼抓它,以及**怎麼知道抓得準不準**。

## 四個零件

| 檔案 | 做什麼 | 靠什麼判斷 |
|---|---|---|
| `scripts/sci_claims.py` | 從 34 張卡 × 兩層 × 兩語 + 字幕 + 宣傳稿裡揀出值得查的句子 | 確定性正則:有外部指涉物,且(有推論詞 或 有帶單位的數字) |
| `scripts/verify_quotes.py` | 「文獻說 X」必須逐字對得上原文 | 確定性:引文正規化後要出現在抓回來的全文/摘要裡 |
| `scripts/disclosure_lint.py` | 專業層承認的模型限制,讀者層不准悄悄不提 | 確定性:站內互比 |
| `scripts/sci_eval.py` | 量上面這些檢查器的鑑別力 | 盲測 + 逐類召回 + 誤報率 + 兩條基線 |

判斷本身(這句推論成不成立)還是要模型或人做。這四支的作用是**把判斷的輸入縮小、把判斷的輸出接地**:
縮小 = 73 句候選而不是全站;接地 = 任何「論文不同意你」都必須附上原文裡的那一句。

## 為什麼引文接地是最重要的一環

`verify_quotes.py` 不接受「我讀過這篇,它說……」。它要的是一段**逐字出現在原文裡**的引文,
正規化只碰排版(NFKC、破折號、彎引號、空白),實詞一個字都不動。所以
`a Gaussian function of angular size` 被寫成 `a linear function of angular size` 會當場對不上。

原文快取在 `audit/sources/`,**不進版控**(論文全文有著作權,本倉不轉散布)。
版控裡留 source id、引文、抓回來那份文字的 sha256 與日期、命中位移——別人重抓一次就能重驗。

## 評估怎麼設計(這是重點)

「這句科學上對不對」沒有 ground truth,所以不量準確率,量**鑑別力**:

1. **語料** `audit/sci_mutants.jsonl`:12 句已驗證為真(每句都標 basis:是親讀文獻驗的,
   還是自家閘門可重算的)+ 21 個變異體,分七類錯誤型別。
   變異體是拿真句子注入指定錯誤、但**用詞一樣乾淨**。每句另標 `needs`(要靠文獻還是自家量測才判得出來)。
2. **盲測**:交給檢查器的題目檔只有不透明 id 與句子,沒有 label 沒有 class。
   ⚠️ 這是**程序上的盲,不是密碼學上的盲**——語料檔就在同一個 repo 裡。
   跑真評估要派沒有本倉脈絡的 fresh-context 檢查者,報告裡要寫明這點。
3. **逐類報告,不報總分**。任一類召回 0 → 整份評估 FAIL,不管總分多好看。
   總召回率會把「某一型別完全抓不到」藏起來。
4. **自動附兩條基線**:always-ok(召回 0 / 誤報 0)與 always-flag(召回 1.0 / 誤報 1.0)。
   任何受測檢查器的數字都跟這兩條並排印,所以「召回 0.9」不可能單獨被讀成好消息。
5. **變異體注入在過濾器上游**:受測的是整條管線,被過濾器漏掉的變異體算沒抓到。

## 第一次實跑(2026-09-17)

兩個檢查器,同一份盲測題目(33 題:21 個變異體 + 12 句已驗證為真)。

| 檢查器 | 召回 | 誤報 | 備註 |
|---|---|---|---|
| 基線 always-ok | 0/21 | 0/12 | 七類全部零召回 |
| 基線 always-flag | 21/21 | 12/12 | 召回滿分但誤報也滿分 |
| `checker_filter.py`(只有過濾器,不含科學判斷) | 11/21 = 0.52 | 4/12 = 0.33 | 確定性下限 |
| **fresh-context opus + 網路文獻(盲測)** | **16/21 = 0.76** | **1/13 = 0.08** | 17 個 flag,13 個附得上 canonical ID |

按「這題要靠什麼才判得出來」拆,結果完全不同:

- **literature(公開文獻就判得出來)10/10 全中,誤報 0/6**。
- **own-data(非有本專案量測不可)6/11**——而我**禁止**它讀本倉。
  那四個「漏抓」量到的是資料取用權,不是科學判斷力,是我的語料設計錯。
  語料因此加了 `needs` 欄,評分可以 `--only-needs literature` 分開看。
  真正要考 own-data 那十題,得把網站公開的事實表一起給檢查器(那些數字本來就是公開的)。

> 表裡的數字是 **2026-09-18 更正後**的。原本記的是 17/21、誤報 0/12;
> 隔天的消融測試把一題的正確答案翻過來(見下面第 3 點),它那一次的 flag 就從命中變成誤報。
> 語料改了,歷史分數就要跟著改——這是這套東西的設計本意,不是瑕疵。

### 這次盲測抓到的三件事,前兩件是我的錯,第三件是它的

1. **我把一句對的判成錯的。** 我原本說卡片裡「巨纖維把兩者**線性整合**」誤述了函數形式,
   依據是 Ache 2019 摘要的「速度的線性函數 + 大小的**高斯**函數」。冷審引 von Reyn 2017 反駁,
   我親查該篇摘要,逐字是「Motor program selection and timing emerge from **linear integration**
   of these two features within the GF」(Neuron 94:1190-1204.e6,PMID 28641115)。
   兩篇不衝突:**整合**(兩個通道相加)是線性的,**通道內**對刺激幾何的轉換可以非線性。
   我把通道內的轉換誤當成通道間的整合——**前提對、推論錯,正是這套系統要抓的那一類,
   而這次犯的人是我**。該條記錄已改成 supported 並留下撤回說明。
2. **語料裡有一句是我自己寫壞的。** 我把網站「果蠅有八種感覺」(逐項列出八種模態)改寫成
   「分成十二類,所以感覺比五種多」,從解剖分類跳到知覺能力。冷審 flag 了它,我同意,
   已改標為 bad 並標 `in_sample`(這個檢查器已經看過它,對它不再是獨立量測)。

3. **它也錯了一題,而且是被實測抓到的。** 它 flag 了「PSI 沒放電是被抑制壓住」,理由與我當初一致:
   真正的原因是模型缺電突觸。2026-09-18 我跑了消融(把進 PSI 的 309 條抑制性邊歸零,其餘不動,
   同協定重跑三個種子):**PSI 三次都放電了**。所以那句歸因成立,它與我都判錯。
   該句在語料裡改標 ok,並補上一個由消融**否證**出來的新變異體
   (「PSI 沒放電是因為突觸只有 16 個」——消融證明那 16 個夠用)。
   真正的缺陷是**省略**,歸 `disclosure_lint` 管,不是這個語料的錯誤型別。

### 過程中修掉的三個系統缺陷

- 第一版過濾器只認「推論詞 + 實體」,unit-or-denominator 與 model-as-biology
  **兩整類在過濾器就死了**。補上「數量 + 實體」之後候選 14 → 73 句才活過來。
  ⚠️ 這一版是看著評估結果改的,那兩類的數字已是 in-sample。
- `checker_filter.py` 自己再寫了一次判斷式,過濾器改了它沒改,兩張表漂開,
  數字紋風不動。現在判斷式只有 `sci_claims.is_candidate()` 一處。
- **`disclosure_lint` 差點恆真通過**。修內容時我把專業層那句「PSI 被驅動得又弱又慢」改寫掉了,
  受限清單瞬間變成空集合,閘門於是 PASS——不是因為修好了,是因為它沒有東西可守。
  現在:空集合直接 FAIL,而且 `EXPECTED_LIMITED` 凍結了預期受限的實體,掉一個就報。
  「全滅才報」擋不住部分退化,這是本專案第三次踩到同一個形狀。

## 這套東西管不到什麼

- **沒有文獻可對的自家量測**——歸 `audit_numbers` / `audit_claims` / `verify_playground`。
- **教學法本身的錯**(比喻會不會讓小孩建立錯的心智模型)——只能靠人。
- **變異體只涵蓋我們想得到的錯法。** 七類是從本專案真的踩過的坑長出來的,不是窮舉。
  所以能寫的只有「這七類的召回是 X」,**不准寫「它擋得住科學錯誤」**。
  任何人示範出一個活下來的稻草人,那個稻草人就永久加進語料,不刪。
- **同家族模型共享盲點**,而 codex 在這台機器上因沙箱問題不可用。
  目前的第二視角是文獻本身:模型只負責揀出要查的那一行,論文才是異質審查者。

## 怎麼跑

```bash
python3 scripts/sci_claims.py                      # 揀候選 → audit/sci_claims.tsv
python3 scripts/verify_quotes.py --fetch           # 抓原文進快取並逐字驗(要連網)
python3 scripts/verify_quotes.py                   # 之後離線重驗
python3 scripts/disclosure_lint.py                 # 限制揭露傳播 → audit/disclosure.tsv
python3 scripts/sci_eval.py --make                 # 產生盲測題目與答案
python3 scripts/sci_eval.py --run "<檢查器指令>"     # 跑並評分,自動附兩條基線
python3 scripts/sci_eval.py --score a.jsonl --only-needs literature --drop-in-sample
```
每支都有 `--self-test`,跑的是**指名的那幾個**負向案例(見各檔 docstring),
不是「擋得住錯的東西」的證明——這個分寸見 README 的閘門段。
